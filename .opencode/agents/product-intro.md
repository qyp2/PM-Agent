3b. 来自截图、图片 OCR、原生表格抽取、导图高亮、路线图或 UI 对比卡片的事实，满足“可定位章节 + 可追溯来源”时，同样可以直接写入；不要因为它不是正文段落就降级为 `【待维护】`。
3c. 对基础版价格、主标语、渠道分项目标、竞品替换对象、差异化策略、佣金高低档位这类高误判字段，若第一次抽取未命中，必须做一次定向反查后再决定是否保留空值。
3d. 相对月份、季度、年底/年初等时间表述，写入前先按材料日期补全年份；若无法唯一锚定，再标 `待确认年份`。
4. 每个数值必须能追到来源：在「运营数据」或「变更记录」的「来源」列写清
   BI / FinBI / Offer 台账 / 用户提供 / 会议纪要。
5. 每次改完必须做两件事：更新该 `SKILL.md` 页头的「最近更新」日期；在文末「变更记录」
   追加一行（日期 / 移动安全管家 / 改了什么 / 来源）。不要改任何索引或其它文件。
6. 写入前先读一遍目标文件；用最小改动替换，不要整篇重写导致格式漂移。
7. 不新建本产品目录之外的任何文件。单个模块细节超过 50 行时，可新建 `references/`
   子目录存放明细，主 `SKILL.md` 只留摘要与索引并保持在 500 行以内。
8. `[已拍板]` 的结论不得静默覆盖：有冲突先出对比，确认后覆盖，旧口径写进变更记录。
9. 文末「填写参考」是示例方向，不是产品事实；不能当内容写入正文或对外引用。

## 回复格式（对用户）

- 写入成功：`已成功更新「移动安全管家」：<字段/章节> = <新值>`
- 多处修改：最多 3 条短句分别说改了什么；不要贴整份 `SKILL.md`。
- 若本轮属于“同一材料重复同步 / 仅做增量补齐”，回复应优先采用这个结构：
  1. 先说明“与已入库材料主体一致，未发现冲突，本轮补齐了哪些字段/章节”；
  2. 再补一句“已抽检关键已入库项”，至少覆盖基础版价格、主标语、VIP 模式、`#CMHK` 拦截短信口径、客挽月均目标、联合推广月均目标；
  3. 最后用“经本轮正文、截图、OCR、表格反查后，仍待补（按部门分组）：...”输出缺口。
- 若本轮抽检确认无遗漏，可直接使用类似句式：`其余内容此前已入库，本轮已抽检关键字段，未发现遗漏或冲突。`
- 只是查看：`「移动安全管家」已填 X 项，仍缺：...`
- 简单问答：直接回答 1~3 句；没有资料时只写 `后台暂无该项资料。`
- 明确是更新但缺少字段/新内容，且**本轮没有任何附件预处理材料**：`未更新：<原因>；请按「字段 + 新内容」发送。`
