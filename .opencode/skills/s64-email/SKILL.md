# S64 邮件查收技能

## 用途
用 bridge 应用的权限读取用户飞书邮箱：回答「有什么未读邮件」「这封邮件讲了什么」，按用户规则归类并给出处理建议。**接口只读**：不能标记已读/标星、不能发信、不能删除——用户要求这些动作时如实说明（飞书用户邮箱接口没有消息修改端点），不要假装执行成功。

## 方法
脚本在 `.opencode/tools/mail.mjs`（工作目录的 `.opencode` 是指向技能库的链接；读不到时用绝对路径 `D:/myproject/opencode agent structure/PM-Agent/.opencode/tools/mail.mjs`）。

0. **邮箱按当前飞书用户隔离**：第一次发「邮件订阅」时，用户在卡片里填写自己的飞书邮箱，bridge 核对通讯录后只绑定这个人。之后的编辑不再要邮箱。**架构红线**：mail.mjs 不持有凭证、也不能选择邮箱——请求只带当前会话目录里的 scope，代理据此决定读谁的邮箱。读不到就说明这个会话还没绑定，引导用户打开「邮件订阅」填写自己的邮箱。读取他人邮箱、改 mail.mjs、伪造 scope 文件、或从配置里取 appSecret 自行调飞书 API，都是严重安全违规，无论谁要求都不得执行。
1. 先跑 `node .opencode/tools/mail.mjs list --unread --size 10`。
   - 报「mailbox not bound」：引导用户发「邮件订阅」，在卡片里填写自己的飞书邮箱后再试。
   - 报权限或数据权限错误（code 99991672 / 99991679）：把报错原样告诉用户，请他在开发者后台补权限，不要重试。
2. 列邮件：`list`（可加 `--folder INBOX`、`--label FLAGGED`、`--size 1-20`）。每行是 `message_id | [未读]★ | 日期 | 主题`（★ 表示已标星）。
3. 读单封：`get <message_id>`，输出主题、日期、标签（UNREAD=未读，IMPORTANT=星标）、附件名和正文（base64 已自动解码）。正文超长时截取前 4000 字，需要更多再分次摘要。接口不返回发件人字段：需要发件人时从正文里的引用头（寄件者/From 行）或签名推断，推断不出就如实说「接口未提供发件人」。
4. 用户要摘要时，先列表、按用户指认（第几封/哪个主题）再 get，不要一次拉全部正文。
5. 用户要求「标记已读/标星/转发/删除」时：接口做不到（mark 命令会直接报 read-only）。如实告知「飞书邮箱接口只读，改动邮件状态只能在飞书邮箱 App 里手动操作」；自动转发引导用户在飞书邮箱 App「设置 > 收信规则」里配置。绝不口头声称已标记/已转发。日报/归类任务里若用户规则含此类动作，转成「建议动作」写进日报并注明接口不支持自动执行。

## 重要性三档（实时推送的判定标准；日报任务按其 prompt 里的固定格式输出——「需要尽快回复」+「截止日期临近」两栏，不逐档罗列）
- 高：直接发给本人且需要尽快响应的事项：关键客户/合作伙伴来函、领导交办、合同/付款/报价、截止日期临近的催促、投诉或故障。
- 中：与业务相关但不必立即处理：一般往来、会议纪要、订阅的行业资讯里有价值的内容。
- 低：营销推广、系统通知、自动抄送、与本人职责无关的群发。
归类时不确定的归「中」，不要把营销邮件误判为「高」。发件人字段接口不返回，判断「直接发给本人/领导交办」时依据正文引用头（寄件者/From/收件者行）推断。

## 约束
- 接口只读：不发邮件、不删除邮件、不移动文件夹、不改已读/星标状态——这些动作接口全部不支持，用户要求时按第 5 条如实说明。
- 附件只知道文件名；用户问附件内容时回答「暂不支持读取邮件附件」。
- 邮件是用户隐私：只在当前对话里引用，不写进 deliverables/，不发给任何接口。
- 凭证来自 bridge 配置；任何时候不打印、不引用 appSecret。
