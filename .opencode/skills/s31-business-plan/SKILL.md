# S31 产品商业计划书技能

## 用途
在完成需求导入的 OA 审批后，产出用于**产品规划及开发评审会**及公司领导专题办公会汇报决策的《XX产品商业计划书》PPT。

本技能结构以公司《产品规划及开发评审会》模板为准。除标注「如适用」的章节外，其余章节都必须有实质内容，不得用空话占位。

## 格式
- 成品是 **PPT**。任务说明已写输出 PPT，或写了「不要再询问」时，直接按下面章节写，不要再问 Word 还是 PDF。
- 封面写明：产品名称、部门、对接产品经理、市场侧对接人（如有）、日期。

## 结构（按此顺序成稿）

### 01 市场分析

#### 1.1 需求分析（必须）
- 以客户价值需求为导向，对标业界，聚焦公司战略及产品能力，充分陈述市场分析情况。
- 明确目标市场、目标行业（ToB）、目标客户需求及痛点。

#### 1.2 竞品分析（必须）
- 竞争对手对标；集团、省分公司同类产品对标。
- **必须体现竞争对手的市场定价**，作为后续产品定价的支撑依据。

### 02 产品方案

#### 2.1 产品简介（必须）
介绍产品功能、卖点、应用场景。

#### 2.2 产品定价（必须）
- 定价坚持成本导向、价值导向、市场导向三大原则：以产品直接成本、营销业务成本、网络成本、人工及行政成本为底线，足额覆盖综合成本；结合核心竞争力与规划路径核定价格；对标香港主流竞品定价，保持竞争优势。
- **写明依据哪项定价原则，以及定价支撑依据。**
- 给出定价表（可用 Markdown 表格，成稿时转幻灯片表格）：

| 产品名称 | 详细内容 | 成本（HKD） | 计费模式 | 合约期 | 资费（HKD） | 利润率 |
| --- | --- | --- | --- | --- | --- | --- |
| … | 服务内容与期限等 | … | 一次性/周期性 | … | … | … |

#### 2.3 生态运营模式（必须）
1. 产品销售渠道、销售模式。
2. 产品运营 / 推广方式。

#### 2.4 产品收入列支（必须）
明确产品可列收通服收入的比例。

#### 2.5 合作伙伴选型（如适用）
仅在确实涉及外部合作时撰写；不适用时写一句「本次不涉及外部合作伙伴选型」即可，不要编造伙伴。
若适用，须覆盖：
1. 合作需求描述（合作方提供什么、合作内容）
2. 合作伙伴资质、能力与过往案例
3. 选型方式：询价 / 单一来源；多家比选须附比选依据
4. 合作分工、付款周期
5. 商务模式：买断 / 联合开发 / 授权
6. 结算条件及模式：底价结算 / 分成结算  
定义以《产品管理办法》为准。

#### 2.6 产品投入产出（必须）
1. 潜在市场规模与投入产出分析。
2. 营销方式：如何让客户买单。
3. 如涉及佣金，必须单独体现佣金成本。当前估算口径：所有渠道先按 **12 个月合约期给 1 个月佣金、24 个月合约期给 2 个月佣金**。
4. 给出三年表：

| 分类 | 第一年 | 第二年 | 第三年 |
| --- | --- | --- | --- |
| 预估收入（通服收入） |  |  |  |
| 结算成本 |  |  |  |
| CAPEX（按年度分摊） |  |  |  |
| OPEX |  |  |  |
| 佣金成本（如涉及） |  |  |  |
| 成本合计 |  |  |  |
| 利润率（收入-成本）/收入 |  |  |  |

#### 2.7 产品内部体验 / 客户体验内测计划（必须）
1. 明确是否计划于产品上线前开展内测。
2. 不开展：详述具体原因。
3. 开展：写明内测时间、内容（订购 / 交互 / 功能 / 性能等）、招募方式与范围、人数、体验时长、反馈收集方式、激励；须符合当年 OA 申请的内测机制。说明由各渠道代表共同评估该计划。

#### 2.8 售后维保（必须）
1. 外部：涉及外部供应商时，明确售后维保条款。
2. 内部：明确内部售后流程与故障解决 SLA（可按 ToB / ToC 实际场景选用模板参考口径，但须改成该产品真实分工，不得原文照抄占位）。

#### 2.9 跨部门分工计划（必须）
写明售前、售中、售后阶段各部门责任。可参考模板角色（产品中心、市场部、政企客户部、网络部、信息技术中心、政企交维、工程建设部、网络管理中心、客户服务中心等），**按本产品实际分工修改**，不要整段照搬。

#### 2.10 产品化计划时间表（必须）
明确合同签署、系统开发、产品体验内测、产品发布、产品培训等节点的计划时间。

### 风险评估与应对措施（必须）
1. 识别内部风险（技术、产品落地、资源不足、需求落地偏差等），并整合内外部风险。
2. 评估各风险等级。
3. 制定规避 / 缓解措施。
4. 明确应对责任人、时间节点，以及预警与应急处理思路。

### 结尾与附录
- 材料来源可注明：需求部门需求导入；基于需求调研报告由产品经理补充。
- 结尾用「以上为产品方案，提请评审。」商业计划书不要写成请示，不要写「请领导批示」。
- 如有需要，附：附录-需求范围、附录-功能详细说明。

## 输出
- 按上述章节组织的商业计划书正文（适合转 PPT）
- 定价表与三年投入产出表
- `gaps`：资料不足、标了「如适用」但未判断是否适用、或标了`【待确认】`的条目

## 约束
- 除「如适用」章节外，不得省略模板必有章节。
- 不编造融资结果、签约结果、真实财务事实；缺数时用区间并标`【假设】`/`【待确认】`。
- 报价、结算条件、对外承诺需人工审批（R-11）。
- 售后 SLA、跨部门分工只能按实际改写，禁止把模板参考表原样当作本产品方案。

## PPT 页题与空表
- 页标题只用不超过 12 个字的章节名，例如「市场分析」「产品定价」。结论写成陈述句，放在该页第一条。禁止写「判断：」「市场分析判断：」这类思考标记。
- 每页最多 4 条短句，每条不超过 40 个字。不要把整段论述贴进一页。
- 封面只写产品名、文种「商业计划书」、汇报对象。不要沿用模板里的旧产品名、旧公司、旧日期。
- 资料里已有的数字必须原样写入，不能改成`【待确认】`。
- 三年投入产出必须做表。资料里有用户量和资费时，按它们估算年收入并标注`【预估】`。没有用户量时，用 1 万、3 万、5 万三档`【假设】`规模，乘以资料中的月费区间，写明年收入，并写明不作为批示依据。不要只留一句「材料未提供」。
- 只有两个整数、不能支持结论的对比，不要做图。
- 不要把填写规则写进幻灯片正文。结尾是「以上为产品方案，提请评审。」
