# S63 幻灯片大纲

## 用途
本技能只规定幻灯片怎么标记，不规定写什么。章节、结论、表格、数字和结尾以业务技能已经写好的正文为准，尤其是 `s31-business-plan`、`s32-product-packaging`、`s33-product-exit`。不要另起提纲，不要删节，不要改写句子，不要把技能要求保留的表格换成图。

用户要 ppt 或 pptx 时，在落盘前把每一节标成下面的结构。成稿命令套用母版 `pm-agent.potx` 的封面版式（`3_自定义版式`）与内容版式（`统一模板`），自动补封面页、页码，并在节数 5–8 个时补一页目录。一个 `##` 是一节；正文写不完会自动续页，表格、图表各自单独成页，后续页标题带「（续）」。正文不要再写「目录」「封面」「谢谢」。明细和多列清单保持 Markdown 表格。只有业务技能要求配图、或上游已经把一组数字写成占比、趋势、对比时，才用下面的 `chart` 块，同一组数字不要又写表又画图。没有模板时使用仓库自带母版，不依赖外部转换器。

标记不只是分页：同一个 `##` 里的写法决定版式。本节第一段是页首导语，2–4 条「数字 + 说明」是指标卡，`### 小标题` 是分栏卡片，有序列表是编号流程，节末的 `>` 是底部结论条，`---` 是章节过渡页。整节全是长段落时只会排成要点列表，尽量按业务内容本身该有的形态来标。

## 每一节

```markdown
## 页标题
副标题点明这一节

这一节用完整句子写清楚，保留名称、数字和时间，不要把一段话收成一个词。

- 要点
- 要点
```

占比用：

```chart pie
| 项目 | 占比 |
| --- | --- |
| 名称 | 原样数字 |
```

趋势用柱状图：

```chart column
| 项目 | 数值 |
| --- | --- |
| 名称 | 原样数字 |
```

对比用条形图：

```chart bar
| 项目 | 数值 |
| --- | --- |
| 名称 | 原样数字 |
```

### 指标页（2–4 条，数字开头）

```markdown
## 关键数字

- 1,633万 2029 期末 ARR｜自下而上测算
- 4–5个月 SaaS 现金回本｜2029 口径
- 约 9–10x SaaS LTV/CAC｜CAC 0.6–0.66 万
```

数字在前、说明在后，`｜` 之后是口径注释（排成卡片底部小字）。数字保持原文并带单位
（`%`、`万`、`个月`、`倍`、`人`…），说明 22 字以内。业务正文本来就是「数字 + 单位 + 名称」时
直接沿用，不要为了凑卡片改数字或换单位。

### 三栏卡片（`###` 小标题 + 一句短话或 2–3 条要点）

```markdown
## 三条主线

### 订阅为体

按坐席年付，覆盖 60% 收入

### 用量为阀

超量按次计费，抑制滥用
```

一页 2–3 个卡片；业务正文本来就是「A ／ B ／ C 三块」对照时用这种标法，不要拆成三页。

### 流程页（`1. 2. 3.`）

```markdown
## 最短价值闭环

1. 问数：一句话把业务问题转成查询
2. 出图：30 秒给出可解释图表
3. 推送：按周推到群与看板
```

每项写成 `步骤名：一句说明`，最多 5 步；步骤名 16 字以内。

### 金句页（整节只有一句话）

```markdown
## AI 让分析内容的消费者变成生产者

> 到 2026 年，90% 的分析内容消费者将借助 AI 成为内容生产者。—— Gartner 预测
```

一节里只放一条 `> ` 引用、或只有一句话时排成整页金句，不会留一张空白要点页。

### 章节过渡

在上一节末尾写一行 `---`，下一页会生成新一节的过渡页（大号章节号 + 标题）。只在
业务正文本身分段（如「市场 / 产品 / 财务」）时使用，不要每节都加。

### 结束页

```markdown
## 结尾

让每个业务人员都拥有自己的分析师

GA 2027-04-15 · 2029 目标 ARR 1,633 万（自下而上测算，非业绩承诺）
```

`## 结尾`（也可写 `致谢`／`谢谢`）排成结束页：第一段是大字，第二段是落款行。业务技能已经
写了结束语时直接搬过来，不要另写。

## 成稿命令

页面写好后，只运行这一条命令。不要再找别的转换器，也不要另写说明文件。

`node ../.opencode/tools/build-deck.mjs --markdown "deliverables\文件.md" --out "deliverables\文件.pptx"`

需要套用用户给的模板时再加 `--template "模板.pptx"`；不传时用仓库自带的
`.opencode/templates/master/pm-agent.potx`。命令是自包含的（不依赖 Feishu-Bridge
或任何外部转换器），路径含空格时保留双引号。不要自己打开 pptx。

命令成功时只打印一行 JSON，例如
`{"ok":true,"path":"...","bytes":9182232,"slides":19,"layouts":[...],"warnings":[]}`。
`warnings` 非空表示有条目超额或字号被压缩，回传 A0 时要说明；`ok:false` 时把
`message` 原样引用，不要给出 pptx 路径。

## 规则
- 一个 `##` 是这一节的主标题。这一节可以变成多页：正文写不完会自动续页；正文超过 5 条要点续页，表格超过 7 行续页，图表单独成页。不要为了塞进一页而删句子。
- 标题下面单独一行、不超过 28 个字、并且不以句号、叹号或问号结尾的短句，才会显示成副标题。这是版式识别，不要为了凑成副标题去改写句子。更长的句子，以及带句号的句子，是正文。
- 本节第一段不超过 64 字、或后面接流程/表格/图表/分栏时，会成为页首导语。导语是版式位置，不是新写一句摘要：直接用业务正文的第一句。
- 要点用 `- `。一段写不完就继续写，不要为了本技能把业务句子改短。
- 2–4 条「数字在前、说明在后」的要点排成指标卡；数字必须带单位，说明 22 字以内，`｜` 后可写口径。业务正文的数字不成组时保持普通要点。
- 三栏卡片用 `###` 小标题，每个小标题下写一句短话或 2–3 条 `- `；一页 2–3 个卡片，超过 3 个另起一页。
- 流程用 `1. ` 有序列表，每项 `步骤名：一句说明`，最多 5 步。
- 多列清单、名单、需要逐项对照的数据，以及业务技能要求保留的表（定价表、三年投入产出表等），写成 Markdown 表格。
- 只有上游已经给出占比、趋势或对比、并且业务技能没有要求这组数字必须留在表里时，才写成 `chart`：占比用 `pie`，趋势用 `column`，对比用 `bar`。第一行是表头，后面每行一个名称和一个数字，最多 8 行。数字保持原文，不要改单位；需要单位时写在围栏行里，例如 `chart bar 单位:%`。不要为了凑齐三种图而改分类。
- 图表按原生形状绘制（不嵌入 Excel 对象），换机器不会变形：`pie` 是 100% 堆叠条 + 图例，`column` 是竖柱，`bar` 是横条。
- 节末的 `> ` 引用排成这一页底部的结论条，一节只写一条，内容用业务正文里已有的结论句。
- 节数在 5–8 之间时自动补一页目录；更多节时不补（目录会挤），改用 `---` 分章。
- 不要写 `**加粗**`、`__下划线__`、行内代码或图片语法。
- 没有内容的节写一行 `- 未提供`。
- 不要写目录页和尾页，命令会按母版补上；结束语只写 `## 结尾` 一节。
